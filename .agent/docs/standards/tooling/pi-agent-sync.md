# pi-agent-base Sync Contract + Generated Bridges

- `pi-agent-base/` is opaque to chezmoi placement (not `dot_*`).
  `run_after_sync-pi-agent-base.sh.tmpl` deploys it to `~/.pi/agent` after every apply in two
  passes: (1) `rsync -a --delete` for plain files; (2) each `*.tmpl` rendered via
  `chezmoi execute-template` to its non-.tmpl name, `chmod 600` (secrets inside), e.g.
  `models.json.tmpl → ~/.pi/agent/models.json` (script lines 60-80).
- **Runtime state preserved, never checked in** — rsync excludes `auth.json`, `sessions/`,
  `bin/`, `git/`, `*.tmpl` outputs, `*.bak*`, `**/.git/` (lines 38-48). NEVER put these in
  pi-agent-base/; NEVER edit `~/.pi/agent` directly — `--delete` clobbers manual edits.
- Templates needing secrets require `BW_SESSION`; bare `chezmoi apply` without it fails
  loudly by design (lines 18-22, 71-75). Deploy via `cma`.
- Pi extensions (`pi-agent-base/extensions/*.ts`, kebab-case) use
  `export default function (pi: ExtensionAPI)` + `pi.on("session_start"|…)` — the one place
  default exports are the convention (extensions/auto-unescape-paths.ts:8-36).
- **`.omp/` and `.claude/` are GENERATED bridges — never hand-edit.** `harness sync`
  regenerates them from committed `.agent/`: symlinks + glue stamped
  `GENERATED by harness sync — do not edit` (harness/src/commands/sync.ts:238-247,
  .omp/config.yml:1). State hash-tracked in `.agent/.sync-manifest.json`; both dirs
  gitignored via the managed `# >>> harness … <<<` block. To change bridge content, change
  `.agent/` (or the harness adapters) and run `harness sync`.
  Exception: `.claude/settings.json` is key-**merged**, not overwritten — sync manages only
  the SessionStart hook, preserving user keys (sync.ts:160-200).
