### What was built

- `lua/util/undo.lua` — the undo-guard module: `hold` (load a file before an agent rewrites it so
  'undoreload' absorbs the write instead of nvim discarding the content-hashed undofile),
  `candidates`/`arm` (7-day windowed startup preload), `release` (cap eviction), `advertise`/
  `unadvertise` (publish this instance's existing msgpack-RPC socket), plus the first-visit
  re-attach that gives a held buffer its filetype back.
- `scripts/undo-guard-notify.ts` — Bun notifier: picks a live instance by longest cwd prefix,
  speaks msgpack directly to the socket nvim already listens on (26ms total; a
  `nvim --server` subprocess would cost ~40ms of process start alone), fails open on every path.
- `scripts/undo-guard-paths.ts` — shared shell-command path extractor (`sed -i`, `tee`, `>`,
  `patch`, `mv`, `cp`, `install`), used by both harness hooks.
- `scripts/undo-guard-omp-hook.ts` — omp `tool_call` hook, installed once at user level via
  `~/.omp/agent/config.yml#extensions`.
- `~/.claude/settings.json` — `PreToolUse` groups for `Write|Edit|MultiEdit|NotebookEdit` and
  `Bash` (outside chezmoi, so not in this diff).
- `lua/plugins/ui/barbar.lua` — `get_unique_name` rewritten (one memoised
  `getbufinfo({buflisted=1})` instead of a per-tab scan of every loaded buffer with a vimscript
  call per iteration), plus `schedule_render` coalescing and replacements for barbar's own
  pure-render `{BufEnter,BufNew}` / window-event / `DiagnosticChanged` autocmds.
- Docs: two decision records, `standards/lua-style/autocmds.md` (5 lessons), refreshed
  `perf-baseline.md`, and 8 per-step verify scripts + `e2e.sh` under the spec directory.

### Decisions made

- Preload windowed to 7 days rather than unwindowed: measured 37 candidates / 29ms / +5.7MB vs
  287 / 151ms / +25.4MB (vex: 469 / 385ms / +57.1MB, per nvim process). Skipping a file never
  shrinks its tree — it only leaves that file unprotected for the session.
- omp hook installs through `config.yml#extensions`, not a `hooks/` directory: probes proved
  `~/.omp/agent/extensions/` and an absolute `extensions:` entry both load, while
  `~/.omp/agent/hooks/` never does. An earlier draft cited two type files as evidence for the
  `hooks/` root; neither exists in the installed package.
- Hook file lives in the chezmoi tree with one absolute-path line outside it, so only a single
  line is unversioned.
- barbar: replaced its pure-render autocmds instead of wrapping `render.update`. Wrapping would
  also catch animation frames (driven by its own timers) and make tabs stutter. `VimResized` was
  deliberately left to barbar so resizes still repaint immediately; its `BufDelete`/`BufWipeout`
  handler was left alone because it also updates jump-mode letters and the recently-closed list.
- Verify lines in `spec-tasks.md` became `bash …/verify/step-N.sh`: `harness implement verify`
  executes that text, and prose Verify lines hung until the 300s timeout.

### Problems hit

- Four spec-authoring bugs surfaced during implementation: `Bun.file(x).exists` is a method (so
  the dead-socket guard never fired), `M.candidates` did not resolve symlinks (zero candidates for
  any project behind one, incl. `/tmp` on macOS), Claude Code's schema needs a nested `hooks: []`
  array not the invented `handler: {}`, and the `patch -p1 < f` case assumed `<` sat adjacent to
  the command name.
- `augroup()` passes `clear = true`, and Step 2 called it twice for one name — the second call
  deleted the `VimEnter` advertise autocmd, so the feature was entirely dead after the first
  apply. Step 2's verify now asserts the live group holds both events.
- Held buffers clobbered harpoon pins: `hold` unlisted (and deleted, when history was stale)
  buffers it had not created. Fixed with a `bufexists`-before-`bufadd` ownership check; then a
  second round, because adopted buffers were excluded from the re-attach table and opened with no
  filetype/LSP until closed and reopened.
- Repeat holds of a historyless file created and destroyed a buffer each time, and the delete ran
  after `eventignore` was restored — leaking `BufWipeout`/`BufUnload` into barbar (5617 renders,
  24s CPU, tabs visibly rearranging). Fixed by suppressing the whole window and caching the
  verdict per path.
- `M.arm`'s finish path was not idempotent: queued `schedule_wrap` callbacks closed an
  already-closing timer handle.
- Three of my own probes reported stale behavior because `nvim -u NONE` keeps `~/.config/nvim` on
  runtimepath and its loader beats `package.path`, so `require("util.undo")` loaded the deployed
  copy. Separately, barbar cannot be exercised headlessly at all — no UI means `VeryLazy` never
  fires. Both are now written into the standards.
