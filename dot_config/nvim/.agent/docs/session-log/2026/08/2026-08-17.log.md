- `lua/util/perf-probe.lua` + `plugin/perf-probe.lua` — interactive performance

### Decisions made
- **Gate the highlighter, not the injections.** 428 of ~460 injected regions in a
  3761-line spec are `markdown_inline`, injected by Nvim core — unreachable from
  `after/queries/`. Editing our own query was worth at most 27%. Stopping the
  highlighter for large markdown removes the per-line multiplication instead.
- **Keep render-markdown.** Verified it re-renders with the highlighter off (all
  extmarks restored via its own `ui.update`), so the gate costs only raw-buffer
  treesitter colouring, which regex syntax + `markdown_fenced_languages` replace.
- **`;; extends` restored** after measuring it post-gate: +28% per markdown
  re-resolution ≈ +48ms per 2-minute session, versus multiplying into a 1.1s
  stall before. Affordable only because of the gate — noted in the query file.
- **Semantic tokens left on** (1226ms max): cost is per document version, not per
  action, and it materially improves TS highlighting.
- **`document_color` guard reverted.** It disabled the feature but requests kept
  firing — lost the swatches, saved nothing. Recorded as do-not-retry.

### Problems hit
- **Headless profiling cannot see this class of bug.** Redraw/tabline/picker cost
  is invisible without a UI, and redraw cost was the whole answer. Seven claims
  died on contact with real-session measurement (LSP attaching to markdown, LSP
  latency from the open spec, eslint blocking saves, the `vim.notify` mirror,
  gitsigns blame, treesitter-context, `util.root.get`).
- **A named subsystem is not a named cause.** Stack samples pointed at
  `languagetree.lua` for a long time; the fix only landed after finding *who*
  started the highlighter — Nvim 0.12's bundled `ftplugin/markdown.lua:1`, which
  runs before any FileType autocmd. Only `after/ftplugin/` can override it.
- **A satellite fix was silently reverted** because it was validated with
  `loadfile` on the source but never copied to the deployed tree; a later broad
  `chezmoi re-add` pulled the stale deployed copy back over it. Cost a full round
  of testing. Always sync deployed before claiming a result.
- **`table.pack`/`table.unpack` do not exist in LuaJIT.** Using them in the
  decoration-provider wrapper made Nvim *disable* core providers, killing
  treesitter highlighting. Instrumentation now pcalls the inner callback.
- **Calling `is_closing()` on a stored libuv handle is a use-after-free** that
  aborts Nvim and `pcall` cannot catch it. It killed a session mid-census.
  Liveness must be resolved through `uv.walk`.
- `:LspInfo` and friends vanished because Nvim 0.12 ships a native `:lsp`, which
  nvim-lspconfig detects and stands down for. `:checkhealth vim.lsp` replaces it.
