## How agents will use this harness

- Every session starts with `harness doctor` (auto via the platform hooks) and `harness state`.
- Workflows are skills in `.agent/skills/` — invocable as slash commands (`/harness-init`,
  `/dev-spec`, `/sync-spec`, `/commit`, `/summary-prompt`, …) or by natural language.
- The harness-keeper advisor is ON (OMP): a cheap watcher that turns your feedback
  into harness updates, logged in `docs/harness-changelog.md` and relayed back to you.
- Before touching code, agents query the code map (`harness context --for "<task>"`) to load
  exactly the standards that govern the files they will change.
- Learnings flow back into the harness (see `docs/harness-guide.md`, "Where knowledge goes"),
  and `harness sync` recompiles the map after standards change.
- `/commit` runs the project's commit checklist
  (`.agent/skills/commit/references/commit-checklist.md`) before anything ships upstream.

### Old-doc drift corrected (code won)
- **barbar/bufferline reversed**: AGENTS.md claimed migration TO bufferline; barbar is
  `enabled = true`, bufferline `enabled = false`.
- **No auto hot-reload**: changes reach `~/.config/nvim` only via manual `chezmoi apply`.
- **AI plugins inactive**: avante + opencode are `enabled = false` (migrated off), despite
  "AI-native integration" claims.
- **Indentation is NOT "tabs everywhere"**: mixed — tab bytes in hand-authored files,
  2-space in vendored/LazyVim-derived; no stylua.toml exists; options.lua sets expandtab.
  New code: 2-space stylua defaults; editing: match the file.
- **"require at top" wrong for util/**: dominant pattern is lazy-require inside functions
  ("load here to prevent loops", util/init.lua:73).
- **No tmux C-hjkl conflict**: vim-tmux-navigator is remapped to `<a-z>` prefix; barbar
  owns C-h/C-l uncontested.
- **"PascalCase modules" wrong**: modules are `local M = {}`; PascalCase only for
  class-like required locals (LazyUtil, Config, Plugin).
- **Quote-split ("double user-visible / single internal") dropped**: no such split exists.
