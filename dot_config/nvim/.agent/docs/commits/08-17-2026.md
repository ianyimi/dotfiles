# Commits — 2026-08-17

## 06:30

perf(nvim): eliminate multi-second editor stalls and handle leaks

**Markdown highlighter gate.** Any full-screen redraw with a large markdown spec visible cost
~1.1s. Nvim core's highlighter re-resolves injected regions roughly once per visible line, each
pass walking every child tree — 461 regions in a 3761-line spec. `after/ftplugin/markdown.lua`
now stops the highlighter above `vim.g.markdown_ts_highlight_max_lines` (1500), keeps the parser
reachable so render-markdown still renders, and falls back to regex syntax so headings and
fenced blocks stay coloured. `after/ftplugin/` is the only viable override point: Nvim 0.12's
bundled `ftplugin/markdown.lua` calls `vim.treesitter.start()` unconditionally, before any
FileType autocmd runs.

**Satellite scrollbar.** `handlers.render` spawns an async coroutine per handler per window and
every coroutine step costs a `vim.schedule`, so with `current_only = false` satellite produced
3455 callbacks totalling 29s of main-loop time in a 62s session — 88% of all scheduled work.
Draw only the focused window, drop the gitsigns handler (the gutter signs already carry hunk
information), and stop pre-clamping `virtual_line_count`, which added two API calls per
iteration inside per-hunk loops for crash protection a bare pcall already provides.

**Handle leaks.** indent-blankline caches one uv timer per buffer number and never closes it —
the plugin has no BufDelete handler at all, so every Telescope preview buffer leaked one
permanently. Release it on BufDelete/BufWipeout, reaching the private cache through the existing
upvalue helper. Also disable lazy.nvim's update checker, which leaked a timeout timer per
spawned `git fetch` across ~67 plugins and accounted for 173 of 192 open handles.

**Blocking work on the main loop.** chezmoi.nvim's edit-watch ran `chezmoi status` through a
blocking `plenary Job:sync` on every buffer read under the source directory, and was registered
twice, so opening anything in this repo — including `.git/COMMIT_EDITMSG` — paid ~117ms twice
before the buffer appeared. De-duplicate the autocmd and guard it with a deny-list for paths
chezmoi never manages. Separately, raise auto-dark-mode's poll interval from 1s to 60s: it
spawned `defaults read` 191 times for 2483ms of main-loop time in a 192s session, to detect a
change that happens twice a day.

**Interactive profiler.** Add `lua/util/perf-probe.lua`, registered lazily from
`plugin/perf-probe.lua` so `:PerfStart`/`:PerfStop` always exist while the 20KB module stays
unloaded until first use. It detects main-loop stalls via timer lateness, attributes libuv
handles, `vim.schedule`, `vim.defer_fn`, `LanguageTree:parse` and decoration providers to their
creation sites, buckets spans per mark so layouts can be compared, and auto-captures snapshots
every 30s. Headless profiling cannot observe redraw cost, and redraw cost was the entire cause
here — every isolated measurement looked healthy.

Measured across comparable sessions: worst stall 1129ms → 107ms, scheduled callback time 33.2s →
4.0s, Oil float 5s → 18ms, RSS 437MB → 139MB, idle libuv timers 300 → 53.
